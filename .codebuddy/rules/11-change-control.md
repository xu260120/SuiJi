# 11 - Change Control Rules

## 变更分类

### 低风险

通常可以直接处理：

- Bug 修复
- 小型 UI 调整
- 测试补充
- 文档修正
- 小型重构

### 中风险

需要分析影响：

- 数据模型修改
- 状态管理调整
- 路由调整
- 第三方依赖变化
- Design Token 大范围变化
- 模块边界调整

### 高风险

必须特别谨慎：

- 数据库结构修改
- migration
- 历史数据修改
- 核心账务逻辑修改
- 核心导航修改
- 核心产品流程修改
- 大规模架构重构
- 删除大量代码
- Git 历史操作
- force push
- 删除 Repository

---

## 高风险变更前

执行高风险修改前，应说明：

- 修改原因
- 影响范围
- 潜在风险
- 验证方式

如果需要用户进行产品或重大技术决策，应先等待确认。

---

## 范围控制

不要因为发现一个问题，就自动扩大任务范围。

发现 UI 问题，不代表可以顺便重构数据层。

发现架构问题，不代表可以顺便改变产品流程。

发现产品问题，可以提出建议，但不能未经授权直接实现。

---

## 删除

删除文件前确认：

- 是否仍被引用
- 是否有测试依赖
- 是否影响路由
- 是否影响配置
- 是否影响数据

大量删除必须明确说明删除范围。

涉及业务数据删除时，同时遵守 `03-accounting-data.md` 的删除检查项。

---

## 保护未提交修改

如果用户存在未提交的修改，不得为了“让仓库干净”而覆盖、删除或重置（见 `06-git.md`）。

---

## 规则文件本身的修改

发现规则缺失、冲突或不合理时，可以提出修改建议。

但不得自行修改 `.codebuddy/rules/` 下的有效规则。

规则文件的修改须经用户确认（见 `01-project.md`）。

---

## 报告

完成变更后报告：

### 已修改

实际修改的内容。

### 已删除

实际删除的内容。

### 已新增

实际新增的内容。

### 已验证

实际执行的验证。

### 未完成

尚未完成的内容。

### 未验证

已经修改但尚未验证的内容。

### 风险

仍然存在的问题。

测试相关内容按 `07-testing.md` 的完成报告同时说明：已测试、未测试、数据影响、数据库影响。
