# 11 - Change Control Rules

## 变更分类

### 低风险

通常可以直接处理：

- Bug 修复
- 小型 UI 调整
- 测试补充
- 文档修正
- 小型重构

### 中风险

需要分析影响：

- 数据模型修改
- 状态管理调整
- 路由调整
- 第三方依赖变化
- Design Token 大范围变化
- 模块边界调整

### 高风险

必须特别谨慎：

- 数据库结构修改
- migration
- 历史数据修改
- 核心账务逻辑修改
- 核心导航修改
- 核心产品流程修改
- 大规模架构重构
- 删除大量代码
- Git 历史操作
- force push
- 删除 Repository

---

## 高风险变更前

执行高风险修改前，应说明：

- 修改原因
- 影响范围
- 潜在风险
- 验证方式

如果需要用户进行产品或重大技术决策，应先等待确认。

---

## 范围控制

不要因为发现一个问题，就自动扩大任务范围。

发现 UI 问题，不代表可以顺便重构数据层。

发现架构问题，不代表可以顺便改变产品流程。

发现产品问题，可以提出建议，但不能未经授权直接实现。

---

## 删除

删除文件前确认：

- 是否仍被引用
- 是否有测试依赖
- 是否影响路由
- 是否影响配置
- 是否影响数据

大量删除必须明确说明删除范围。

涉及业务数据删除时，同时遵守 `03-accounting-data.md` 的删除检查项。

---

## 保护未提交修改

如果用户存在未提交的修改，不得为了“让仓库干净”而覆盖、删除或重置（见 `06-git.md`）。

---

## 规则文件本身的修改

发现规则缺失、冲突或不合理时，可以提出修改建议。

但不得自行修改 `.codebuddy/rules/` 下的有效规则。

规则文件的修改须经用户确认（见 `01-project.md`）。

---

## 报告（统一格式）

本节是 Suiji **唯一**任务报告格式。其他规则文件与 `CODEBUDDY.md` 直接引用本节，不再另定义字段。

每次重要任务或变更完成后按以下字段如实报告。某项没有内容时写「无」，不得省略字段来掩盖问题。

版权 / 许可风险与参考来源按 `08-ai-behavior.md` 填写，必须在本报告中单独呈现，不得只做口头说明。

### 变更范围

- 已修改：实际修改的文件与内容
- 已新增：实际新增的文件与内容
- 已删除：实际删除的文件与内容

### 完成状态

- 已完成：实际完成并已验证的内容
- 部分完成：已实现但仍有缺口的内容
- 未完成：尚未实现的内容

### 验证

- 已验证：列出实际执行的验证动作与结果
- 已测试 / 未测试：按 `07-testing.md` 如实填写
- 未验证：已修改但尚未验证的内容

### 数据影响

- 数据影响：无 / 有（说明）
- 数据库影响：无 / 有（说明）

### 参考来源与许可

按 `08-ai-behavior.md`「非自主开发内容的参考来源」逐项列出；本次产出全部为自主开发时写「无」：

- 参考来源：名称 + 路径 / URL / 版本
- 参考范围与落点：参考了什么、用在哪个文件或模块
- 改动情况：是否改写、改动了什么
- 许可证 / 授权状态：已知写名称，未知写「无法确认」
- 版权 / 许可风险：事前告知的结论（无风险也须写「无」）

### 风险 / 问题

- 已知问题、未解决风险、需要用户确认的事项；版权 / 许可风险同时在上节呈现

### 信息分级

涉及事实性内容时区分：已确认事实、合理推测、AI 观点、无法验证的信息；不得把推测写成事实（见 `08-ai-behavior.md`）。

> 计划 ≠ 代码生成 ≠ 文件创建 ≠ 功能完成 ≠ 测试通过 ≠ 产品完成。

测试相关内容按 `07-testing.md` 的「测试结果必须真实」填写；不得虚构文件、API、测试结果或外部资料。
